# 07.1 — Conector InHire

Primeira implementação dos contratos de `docs/07-conectores.md`.

| Campo | Valor |
|---|---|
| Key | `inhire` |
| Projeto | `src/JobHunter.Connectors.InHire` |
| Capacidades | `TenantListing`, `PostingDetails`, `ApplicationInspect`, `ApplicationSubmit`, `AssistedApply`, `HealthProbe` |
| Tecnologia | HTTP (`IHttpClientFactory`) nos endpoints públicos da página de carreiras, conforme ADR-009; Playwright só se a spec de envio exigir |
| Tenant | Slug do subdomínio: `https://{slug}.inhire.app/vagas` → `TenantRef("{slug}")` |

## 1. O que já se sabe

- Cada empresa tem uma página de carreiras em `https://{slug}.inhire.app/vagas` (exemplos públicos: `eyxo.inhire.app/vagas`, `db1.inhire.app/vagas`).
- As páginas são SPA: as vagas são carregadas por JavaScript após o HTML inicial.
- Os formulários têm perguntas de triagem que podem funcionar como filtro eliminatório.

Tudo o mais (formato das URLs de vaga, estrutura do formulário, endpoints usados pelo front-end, confirmação de envio) é **hipótese até o reconhecimento**. Não invente endpoints, nomes de campos ou seletores.

## 2. Reconhecimento (fazer antes de codificar)

Faça manualmente, no seu navegador, em **2 ou 3 empresas diferentes**:

### 2.1 Listagem
1. Abra `https://{slug}.inhire.app/vagas` com o DevTools aberto (aba **Network**, filtro **Fetch/XHR**).
2. Recarregue a página. Anote:
   - requisições que retornam a lista de vagas (URL, método, cabeçalhos relevantes, formato da resposta);
   - se há paginação ou "carregar mais";
   - se a resposta depende de algum token/cookie.
3. Salve o HTML renderizado: no console, `copy(document.documentElement.outerHTML)` e cole num arquivo.
4. Salve a resposta JSON da listagem (botão direito → Copy response).

### 2.2 Página da vaga
1. Abra uma vaga. Anote o padrão da URL e onde está o identificador.
2. Salve HTML renderizado e respostas JSON.
3. Anote como aparecem: local, modelo de trabalho, senioridade, tipo de contratação, data.

### 2.3 Formulário de candidatura
1. Clique em candidatar-se **sem enviar**. Anote se o formulário abre na mesma página, em modal ou em outra URL.
2. Para cada campo: label, tipo, `name`/`id`, obrigatório, opções.
3. Como é o upload de currículo (input file, drag-and-drop, integração com LinkedIn?).
4. Existe aceite de termos/LGPD? Banco de talentos?
5. Salve o HTML do formulário.
6. **Não envie** candidatura de teste a uma empresa real só para observar a confirmação. Se quiser observar, faça numa vaga em que você realmente quer se candidatar, manualmente, e anote a mensagem/URL de confirmação.

### 2.4 Proteções
- Há captcha visível ou invisível (reCAPTCHA, hCaptcha, Turnstile)?
- Há exigência de login/conta de candidato?
- Existe `robots.txt` em `https://{slug}.inhire.app/robots.txt`? O que diz?

### 2.5 Higiene das fixtures
Antes de salvar em `tests/.../Fixtures/`, remova qualquer dado pessoal (seu ou de terceiros) e tokens. Nomeie como `listing-<slug>-<yyyyMMdd>.html`, `job-<slug>-<id>.html`, `form-<slug>-<id>.html`, `listing-<slug>.json`.

## 3. Achados do reconhecimento

> Preencher após o passo 2. Esta seção alimenta a spec do conector e os parsers.

Reconhecimento em 2026-10-30 nos tenants `eyxo` (6 vagas) e `db1` (52 vagas): HTML inicial, bundle público da página e 13 requisições somente leitura aos mesmos endpoints que a página chama. Decisão de estratégia em `docs/adr/ADR-009-inhire-via-api-publica.md`.

| Item | Achado |
|---|---|
| Endpoint/estrutura da listagem | SPA (`/static/js/careers.<hash>.js`) que consome `https://api.inhire.app`. Tenant: `GET /tenants/public/config/resolve/{slug}` → `tenant.id` = slug, `tenant.name`, `subdomain.primarySubdomain`. Vagas: `GET /job-posts/public/pages` com `X-Tenant: {slug}` → `{ tenantName, ..., jobsPage: [...] }`. Funciona com User-Agent próprio e só o `X-Tenant` |
| Padrão de URL da vaga | `https://{slug}.inhire.app/vagas/{jobId}/{jobSlug}` (a rota também aceita `/vagas/{jobId}`). Detalhe: `GET /job-posts/public/pages/{jobId}` com `X-Tenant` |
| Origem do `ExternalId` | `jobId` (UUID) |
| Paginação | Não há: a lista inteira vem numa resposta (52 itens em `db1`) |
| Campos disponíveis na listagem | `jobId`, `displayName`, `status` (`published`), `workplaceType` (`Remote`, `Hybrid`, `On-site`), `location` (`"Cidade, UF, BR"`), `careerPageId`/`careerPageIds`. Sem descrição nem data |
| Campos do detalhe | `description` (HTML), `contractType` (ex.: `["PJ"]`), `publishedAt`, `lastPublishedAt`, `workplaceType`, `location`, `locationComplement`, `salaryCurrency`, `status`, `settings.fields`, `settings.requiredFields`, `diversity.questions` |
| Abertura do formulário | Envio por `POST /job-talents/public/{jobId}/talents`; o bundle também referencia `form-app.inhire.app`. Layout do formulário na página: a confirmar na spec 004 |
| Campos padrão do formulário | Configuráveis por vaga em `settings.fields` (observado: `linkedin`, `salary`, `curriculum`, `workModel`) e `settings.requiredFields` (`linkedin`, `salary`, `workModel`). Nome/e-mail/telefone: a confirmar na spec 004 |
| Upload de currículo | Campo `curriculum`; mecanismo a confirmar na spec 004 |
| Aceites/consentimentos | `privacyPolicyUrl` por vaga; perguntas de diversidade opcionais (`diversityGroup`, `genderIdentity`, `sexualOrientation`, `colourAndEthnicity`, `peopleWithDisability*`) são **dados sensíveis (LGPD)** e nunca devem ser respondidas automaticamente |
| Sinal de confirmação de envio | A confirmar na spec 005 (não enviar candidatura de teste). A vaga tem e-mail de confirmação configurado (`settings.email`) |
| Captcha / login | Listagem e detalhe sem login e sem desafio. O cliente público envia `X-Recaptcha` em algumas chamadas (envio de candidatura). Domínio atrás da Cloudflare: desafio anti-bot deve virar `CaptchaDetected` |
| Erros | Tenant inexistente: 404 `{"message":"Subdomain not found","name":"NotFoundError"}`. Vaga inexistente: 404 `{"message":"Job page not found"}` |
| robots.txt | Gerenciado pela Cloudflare. `User-agent: *` com `Allow: /` e `Content-Signal: search=yes, ai-train=no, use=reference` (`ai-input` não declarado: considerar antes de enviar descrições de vaga a um LLM). Bloqueia `/indique-uma-pessoa/` e crawlers de treino de IA |
| Termos de uso lidos em | 2026-10-30: termos de uso não encontrados (`/termos-de-uso` e `/termos` em `inhire.com.br` retornam 404; sem link no rodapé). O tenant aponta `termsOfUseUrl` para a política de privacidade, que não trata de acesso automatizado nem de candidaturas por ferramentas de terceiros. Captura habilitada; envio só depois de verificar os termos |

## 4. Estratégia de implementação

### 4.1 Listagem (`InHireTenantSource`)

Decidido no reconhecimento (ADR-009): `GET https://api.inhire.app/job-posts/public/pages` com `X-Tenant: {slug}`, parsing com `System.Text.Json` em `InHireListingParser`. Cada item vira um `SourcedPosting` com `ExternalId = jobId`, `SourceUrl = ApplyUrl = https://{slug}.inhire.app/vagas/{jobId}`, `CompanyName = tenantName`, `Location`, `WorkModel` (`Remote`, `Hybrid`, `On-site` → `OnSite`). A listagem não traz descrição: o núcleo busca os detalhes das vagas novas na mesma varredura.

### 4.2 Detalhes (`InHireDetailsProvider`)

- `CanHandle(url)`: host termina em `.inhire.app` e o caminho corresponde ao padrão de vaga levantado.
- `GET https://api.inhire.app/job-posts/public/pages/{jobId}` com `X-Tenant`. `DescriptionText` gerado a partir de `description` (HTML) com AngleSharp (`TextContent`, normalizando espaços); `contractType` e `locationComplement` vão em `Extra`.
- Vaga inexistente/encerrada → `PostingClosed`.

### 4.3 Candidatura (`InHireApplicationChannel`)

- `CanHandle(applyUrl)`: mesma regra de host + padrão de URL.
- `InspectAsync`: abre a vaga, abre o formulário, usa `HtmlFormReader` e refina com `InHireFieldSemantics` (ex.: input `type=email` → `Email`; label contendo "LinkedIn" → `LinkedInUrl`; input file com label "currículo" → `Resume`; checkbox de termos → `ConsentTerms`).
- `SubmitAsync`: reabre o formulário, recalcula `FormHash` (diferente → `FormChanged`), preenche com `FormFiller`, anexa arquivo, aguarda o sinal de confirmação levantado no reconhecimento, salva screenshot **sempre** (sucesso ou falha) em `EvidenceDirectory`.
- `OpenAssistedAsync`: igual ao envio, com navegador visível, **sem** clicar em enviar; retorna quando o usuário fecha a janela.
- Captcha detectado em qualquer etapa → `CaptchaDetected` com evidência.

### 4.4 Seletores (`InHireSelectors.cs`)

Todos os locators num único arquivo `internal static`, como funções que recebem `IPage`, priorizando seletores semânticos:

```csharp
internal static class InHireSelectors
{
    public static ILocator ApplyButton(IPage page) =>
        page.GetByRole(AriaRole.Button, new() { NameRegex = new Regex("candidatar", RegexOptions.IgnoreCase) });

    public static ILocator ApplicationForm(IPage page) =>
        page.Locator("form").Filter(new() { Has = page.Locator("input[type=file]") });
}
```

Os valores acima são **exemplos de formato**; os seletores reais saem do reconhecimento.
