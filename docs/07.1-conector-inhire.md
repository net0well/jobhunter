# 07.1 — Conector InHire

Primeira implementação dos contratos de `docs/07-conectores.md`.

| Campo | Valor |
|---|---|
| Key | `inhire` |
| Projeto | `src/JobHunter.Connectors.InHire` |
| Capacidades | `TenantListing`, `PostingDetails`, `ApplicationInspect`, `ApplicationSubmit`, `AssistedApply`, `HealthProbe` |
| Tecnologia | Playwright (via `JobHunter.Connectors.Browser`); HTTP direto **somente** se o reconhecimento mostrar endpoints JSON estáveis e públicos |
| Tenant | Slug do subdomínio: `https://{slug}.inhire.app/vagas` → `TenantRef("{slug}")` |

## 1. O que já se sabe

- Cada empresa tem uma página de carreiras em `https://{slug}.inhire.app/vagas` (exemplos públicos: `eyxo.inhire.app/vagas`, `db1.inhire.app/vagas`).
- As páginas são SPA: as vagas são carregadas por JavaScript após o HTML inicial.
- Os formulários têm perguntas de triagem que podem funcionar como filtro eliminatório.

Tudo o mais (formato das URLs de vaga, estrutura do formulário, endpoints usados pelo front-end, confirmação de envio) é **hipótese até o reconhecimento**. Não invente endpoints, nomes de campos ou seletores.

## 2. Reconhecimento (fazer antes de codificar)

Faça manualmente, no seu navegador, em **2 ou 3 empresas diferentes**:

### 2.1 Listagem
1. Abra `https://{slug}.inhire.app/vagas` com o DevTools aberto (aba **Network**, filtro **Fetch/XHR**).
2. Recarregue a página. Anote:
   - requisições que retornam a lista de vagas (URL, método, cabeçalhos relevantes, formato da resposta);
   - se há paginação ou "carregar mais";
   - se a resposta depende de algum token/cookie.
3. Salve o HTML renderizado: no console, `copy(document.documentElement.outerHTML)` e cole num arquivo.
4. Salve a resposta JSON da listagem (botão direito → Copy response).

### 2.2 Página da vaga
1. Abra uma vaga. Anote o padrão da URL e onde está o identificador.
2. Salve HTML renderizado e respostas JSON.
3. Anote como aparecem: local, modelo de trabalho, senioridade, tipo de contratação, data.

### 2.3 Formulário de candidatura
1. Clique em candidatar-se **sem enviar**. Anote se o formulário abre na mesma página, em modal ou em outra URL.
2. Para cada campo: label, tipo, `name`/`id`, obrigatório, opções.
3. Como é o upload de currículo (input file, drag-and-drop, integração com LinkedIn?).
4. Existe aceite de termos/LGPD? Banco de talentos?
5. Salve o HTML do formulário.
6. **Não envie** candidatura de teste a uma empresa real só para observar a confirmação. Se quiser observar, faça numa vaga em que você realmente quer se candidatar, manualmente, e anote a mensagem/URL de confirmação.

### 2.4 Proteções
- Há captcha visível ou invisível (reCAPTCHA, hCaptcha, Turnstile)?
- Há exigência de login/conta de candidato?
- Existe `robots.txt` em `https://{slug}.inhire.app/robots.txt`? O que diz?

### 2.5 Higiene das fixtures
Antes de salvar em `tests/.../Fixtures/`, remova qualquer dado pessoal (seu ou de terceiros) e tokens. Nomeie como `listing-<slug>-<yyyyMMdd>.html`, `job-<slug>-<id>.html`, `form-<slug>-<id>.html`, `listing-<slug>.json`.

## 4. Estratégia de implementação

### 4.1 Listagem (`InHireTenantSource`)

Ordem de preferência, decidida pelos achados:

1. **JSON capturado pelo navegador**: abrir a página com Playwright e interceptar a resposta da listagem com `page.WaitForResponseAsync(...)`. Parsing com `System.Text.Json` em `InHireListingParser`. Mais estável que HTML e continua parecendo uma visita normal.
2. **HTML renderizado**: esperar a lista aparecer e passar `page.ContentAsync()` para `InHireListingParser` (AngleSharp).
3. **HTTP direto** ao endpoint JSON: somente se for público, sem token, e os termos não proibirem. Exige ADR próprio.

### 4.2 Detalhes (`InHireDetailsProvider`)

- `CanHandle(url)`: host termina em `.inhire.app` e o caminho corresponde ao padrão de vaga levantado.
- Mesmo esquema (JSON interceptado ou HTML). `DescriptionText` gerado a partir do HTML com AngleSharp (`TextContent`, normalizando espaços).
- Vaga inexistente/encerrada → `PostingClosed`.

### 4.3 Candidatura (`InHireApplicationChannel`)

- `CanHandle(applyUrl)`: mesma regra de host + padrão de URL.
- `InspectAsync`: abre a vaga, abre o formulário, usa `HtmlFormReader` e refina com `InHireFieldSemantics` (ex.: input `type=email` → `Email`; label contendo "LinkedIn" → `LinkedInUrl`; input file com label "currículo" → `Resume`; checkbox de termos → `ConsentTerms`).
- `SubmitAsync`: reabre o formulário, recalcula `FormHash` (diferente → `FormChanged`), preenche com `FormFiller`, anexa arquivo, aguarda o sinal de confirmação levantado no reconhecimento, salva screenshot **sempre** (sucesso ou falha) em `EvidenceDirectory`.
- `OpenAssistedAsync`: igual ao envio, com navegador visível, **sem** clicar em enviar; retorna quando o usuário fecha a janela.
- Captcha detectado em qualquer etapa → `CaptchaDetected` com evidência.

### 4.4 Seletores (`InHireSelectors.cs`)

Todos os locators num único arquivo `internal static`, como funções que recebem `IPage`, priorizando seletores semânticos:

```csharp
internal static class InHireSelectors
{
    public static ILocator ApplyButton(IPage page) =>
        page.GetByRole(AriaRole.Button, new() { NameRegex = new Regex("candidatar", RegexOptions.IgnoreCase) });

    public static ILocator ApplicationForm(IPage page) =>
        page.Locator("form").Filter(new() { Has = page.Locator("input[type=file]") });
}
```

Os valores acima são **exemplos de formato**; os seletores reais saem do reconhecimento.
